Where we actually are

Road to 178's own Stage 0 finding is unchanged and still the most urgent thing in this repo: the daily loop dead-letters roughly 400+ tasks every three days because eleven of twelve scan profiles carry no source URLs, and the loop built to fix that (la-source-discovery-trigger) has logged zero events in seven days. Reconfirmed live this session (audit v2 §2): 248 scan_profile_not_configured events over the trailing three days, brief_published firing on 2 of the last 7. Nothing about v2 changes this, and nothing in v2's own build plan should start before it.

Layered onto that: PR #148 (Job 1 of this request) landed 41 new designed items as scaffolding — committed, validated, tested in isolation, wired into nothing. The human-input register scorecard (audit v2 §4) makes the gap explicit: 1 of 30 human-input rows is actually done; 27 are scaffolded but still run the v1 way in production. This plan is what closes that gap, in an order that does not repeat road-to-178's own diagnosed mistake — building fast without the instrument that makes the result reviewable.

2

Done bar, extended for v2

Road to 178 §3's eight criteria, unchanged, plus three v2-specific ones a scaffolded package cannot satisfy by definition — which is exactly the point: "scaffolded" and "done" must stay visibly different states.

  • 1–7 · unchanged — shape validates, five golden evals, safety suite clean, rubric lints, registered and signed, reachable (a loop task_type resolves to it), exercised live once against cmos-dev.
  • 8 · QA gates at target — now measured, not merely designed: audit v2 §2 gives fn 02 at 64.1%, fn 48 at 41.6%, refreshed 4 September.
  • 9 · Emits a valid OptionCard v2 — validates against contracts/option-card.schema.json; ≥1 evidence_refs entry; a declared recommended_option_id.
  • 10 · Evidence refs resolve v2 — every evidence_refs entry with source_type ≠ none resolves via the vault's atom/asset/decision index at card-build time (§C3). This is the structural answer to fabricated-proof-point, still the dominant violation code at 226/30d as of this audit; an unresolvable ref must reject the card, not just flag it.
  • 11 · No default_on_timeout on a downstream card v2 — §G2: timeout defaults are earned per function, upstream only, and never for publish/claim/spend/engage_external/contact_client. A downstream card with a non-null default is a done-bar failure, full stop, not a style note.
3

The merged sequence

Two backlogs exist and both need session capacity: the 80 remaining v1 rows (road-to-178's Stage 2, unchanged) and Appendix D's 13 PRs. They are not independent. Appendix D PRs 1–5 build the card mechanism every future approval — old function or new — should route through; building more of the 80 v1 rows against the old approval path before that lands means touching them again later. So App D PRs 1–5 move ahead of Stage 2's fan-out, but behind Stage 0/1, which fix problems that exist regardless of which mechanism approvals eventually use.

Cadence rules, carried forward unchanged
