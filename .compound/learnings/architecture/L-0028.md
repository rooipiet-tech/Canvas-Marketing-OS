statement: When the same injected-logic (e.g. a bundle/unpack sequence) must exist in two authoring surfaces — an IaC inline command (bicep `loadTextContent`) and a companion verification/test script — author it once as a shared manifest + literal script file consumed verbatim by both, rather than reimplementing it twice. Syntax-only checks (`az bicep build`) cannot detect drift between two independently-written copies of the same logic.

evidence: A plan-reviewer round-2 finding (F-NEW-2, S4 governance build) caught that steps bundling a multi-file Python service into a stock Container Apps image had independently reimplemented the JSON/base64 bundling and unpack logic once in the bicep `command` array and again in a local verify script — a bug only in the bicep copy would pass the verify script cleanly and only surface at the expensive live deploy. The fix (plan_version 3, step 21.5) introduced a single `BUNDLE_MANIFEST.txt` per service plus one literal unpack shell script per service, `loadTextContent`'d into the bicep container command AND subprocess-executed by the verify script, with grep checks that neither authoring surface reimplements the logic inline.

catch_next_time: Plan-review checklist addition (extends [[L-0006]]): whenever a step's `done_when` exercises logic written in two places (IaC inline command + a standalone verify/test script, or any bicep-vs-script pair), require a shared manifest/literal-script artifact consumed verbatim by both, plus a grep check that neither authoring surface contains an inline reimplementation of the shared logic.
