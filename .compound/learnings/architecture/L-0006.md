statement: A structured plan-review pass (run before any code is written) reliably catches a recurring class of IaC/CI architectural gaps: missing workflow `on:` triggers, no mechanism to verify resources reachable only via private endpoint from outside the VNet, unbounded polling loops for async cloud feature-registration flags, ambiguous cross-module credential/dependency wiring, fragile `gh api` ID-resolution patterns, and relative-path assumptions in IaC functions like Bicep's `loadTextContent`.

evidence: Two plan-reviewer passes on the canvas-marketing-os-foundation run found exactly these 6 findings before the builder ran, all fixed in plan v2's change_summary before any code existed; the final plan-reviewer pass then approved with only 3 residual minor notes.

catch_next_time: Maintain this checklist as a standing plan-reviewer rubric for any IaC/CI-heavy build: (1) every workflow file declares explicit `on:` triggers matching the spec's automation intent; (2) any private-endpoint-only resource has an explicit in-VNet verification mechanism, not just an assumption of direct reachability; (3) any poll of an async cloud operation/feature flag has a bounded attempt-count and timeout with a loud failure message; (4) cross-module credential flow is stated explicitly, not left implicit; (5) `gh api` calls needing a resolved numeric ID use a two-step resolve-then-PUT-JSON-body pattern, not fragile inline `-f` array flags; (6) IaC file-loading functions with relative paths have their base directory stated explicitly.
