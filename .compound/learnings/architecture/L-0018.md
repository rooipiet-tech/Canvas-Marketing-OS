statement: An IaC-defined container app whose real image is pushed by a
separate CD pipeline needs a bootstrap-safe default: the IaC template's
image parameter should default to a public, unauthenticated placeholder
image (not a reference into a registry that may not exist or hold anything
yet), and the deploy pipeline that applies the template should resolve that
parameter to the app's CURRENT live image on every run after the first —
never re-apply the placeholder over a real running image.

evidence: gateway.bicep originally hardcoded `${containerRegistryLoginServer}/
model-gateway:latest` with no bootstrap path, so a brand-new environment's
first-ever provision had nothing valid to pull (the registry was empty,
`deploy-gateway.yml` hadn't run yet) — documented at the time as an
"expected transient unhealthy revision," but in practice this combined with
the L-0017 ordering bug to produce a hard deployment failure, not just a
soft unhealthy revision. Fixed by defaulting `containerImage` to
`mcr.microsoft.com/azuredocs/containerapps-helloworld:latest` (a real ACA
quickstart image needing no registry dependency at all) and having the
deploy workflow's preflight do `az containerapp show ... || use placeholder`
before every `az deployment group create`/`what-if`.

catch_next_time: When planning a new Container App (or similar
image-carrying resource) whose real image comes from CI/CD rather than the
IaC template itself, always design the bootstrap path explicitly as part of
the plan, not as a follow-up fix: (1) a public placeholder image as the
template's default, (2) a preflight step in the IaC deploy workflow that
reads the resource's current live image if it exists and passes that same
value back in as an explicit parameter (so a routine infra-only redeploy is
a no-op on the image field), falling back to the placeholder only when the
resource doesn't exist yet. Treat "what happens on the very first deploy,
before the image pipeline has ever run" as a plan-reviewer checklist item
for any new IaC-defined compute resource fed by a separate CD step.
