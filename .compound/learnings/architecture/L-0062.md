statement: "Frozen contract files read at RUNTIME" is a per-service CONCERN, not a per-service SOLUTION — model-gateway's CONTRACTS_DIR pattern (env-var override + checkout-relative fallback, staged into the Docker build context by the image workflow, documented with a full incident writeup in gateway's config.py/Dockerfile) already exists in this repo specifically because a service's Docker build context is scoped to its own `services/<name>/` directory, and `contracts/` at the repo root is unreachable from inside it. A NEW service that reads contract schemas at runtime (not just at build/test time) needs this exact pattern from day one, in EVERY module that resolves such a path — not just the first one that happens to crash.

evidence: On 2026-07-31, ca-orchestrator's maiden real-image deploy crashed on every heartbeat: `loop_loader.py`'s `_SCHEMA_PATH` (a module-level constant, 4 chained `.parent` hops) resolved to `/contracts/orchestrator/loop-definition.schema.json` inside the container — a path that only exists in a full repo checkout, not the image built from `services/orchestrator` alone. Fixing that one call site got the smoke test one step further, straight into an IDENTICAL, independently-computed bug in `producer.py` (`_CONTRACTS_DIR`, 5 chained `.parent` hops, same wrong-inside-the-image math) — envelope validation before every publish. A third instance (`smoke_test.py`'s golden-fixture comparison file) needed a different fix (the Dockerfile's multi-stage build deliberately excludes `tests/`, so the one needed golden JSON had to be staged explicitly) but was the same root discovery: nothing that reads a repo-root file at runtime had been checked against the actual container layout before this incident, even though the identical problem, symptom, and fix were already fully documented for model-gateway.

catch_next_time: When plan-reviewing or building a new containerized service, grep it for every `Path(__file__)`-based resolution (`rg "Path\(__file__\)"`) and every literal reference to a repo-root directory (`contracts/`, etc.) BEFORE the first deploy, not after the first crash. If any resolve a path outside the service's own Docker build context, apply the established CONTRACTS_DIR pattern (services/model-gateway/config.py's `contracts_dir()` + its Dockerfile's staging COPY + the image workflow's "Stage the frozen contracts into the build context" step) to ALL of them in the same pass — a single-instance fix reliably surfaces its siblings one crash at a time instead (see [[L-0013]]'s general form of this lesson). A companion sweep test (assert no module-level `.parent`/`.parents[N]` walk exists outside a short permitted list) catches new instances before they ship, not after.
