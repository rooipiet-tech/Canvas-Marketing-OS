statement: Code that passes every local/CI-executed test suite can still be non-deployable, because local tests exercise application logic, not the actual deployment-packaging mechanism (hand-maintained BUNDLE_MANIFEST.txt/Bicep loadTextContent bundles, a Bicep-hardcoded single-file migration loader, and Bicep env-var wiring for a container's outbound client URLs) — the identical bug class recurred 4 times in one build.

evidence: (1) functions/ dir staging fixed during rebase reconciliation citing L-0062/L-0063 precedent. (2) risk-security RS-01 (blocker): services/gatekeeper and services/publisher's BUNDLE_MANIFEST.txt never got 5 new files added -> real deployed image ImportError-crash-loops; scripts/verify_governance_bundle_reconstruction.py only runs on workflow_dispatch/workflow_run, never on pull_request. (3) migration lens F-1 (blocker): infra/main.bicep's orchestratorMigrationSql loadTextContent loads only 0001_orchestrator_init.sql, never 0002/0003, even though the new code depends on both at runtime; CI tests pass only because conftest.py applies migrations/*.sql via a glob that masks the production wiring gap. (4) agent-native F1 + performance PERF-04 (blocker): all 4 of orchestrator's client base-URL resolvers fall through to an uncached `az containerapp show` subprocess shell-out with zero Bicep env-var wiring, and the image never installs azure-cli, so resolution silently returns None in the real container.

catch_next_time: Add a pull_request-triggered CI check (not just workflow_dispatch/workflow_run) that, for every service deployed via a hand-maintained bundle/manifest, diffs the set of files the service's own code imports/requires against the set of files enumerated in its deploy manifest (BUNDLE_MANIFEST.txt / Bicep loadTextContent var list / Bicep-hardcoded migration file list), and fails on any mismatch. Apply the identical diff-check to Bicep env-var wiring: for every outbound client base-URL a container resolves at runtime, confirm a matching Bicep envVar entry exists. This generalizes L-0062's CONTRACTS_DIR sweep-test from "files a call site reads" to "files/vars a deploy bundle must supply" — make it a standing plan-review checklist item for any new file added to a bundle-deployed service, not something re-discovered per-file by a review lens.
