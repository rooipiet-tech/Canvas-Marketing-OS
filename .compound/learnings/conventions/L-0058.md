statement: `grep -v PATTERN` exits 1 (not 0) when it selects zero lines — precisely the PASSING case for a "no offending lines remain" scope-guard check. A `pipeline | grep -v X` feeding directly into an `&&`-chained assertion breaks the chain and fails the whole verify script on exactly the success case, unless the grep stage's exit code is neutralized.

evidence: On the s11-content run, AC-01's verify command `OFFENDING=$(git diff ... | grep -vE '^(functions/|services/orchestrator/loops/|docs/)') && test -z "$OFFENDING"` failed on every fully-compliant build — confirmed live: re-running it against a diff where every path was already compliant printed FAIL despite `$OFFENDING` being empty, because `grep -v` selecting zero lines exited 1 and broke the `&&` chain before `test -z` ever ran. Fixed by appending `|| true` to the grep stage.

catch_next_time: When writing an "assert nothing matches" verify command as `X=$(pipeline | grep -v PATTERN) && test -z "$X"`, always neutralize grep's exit code with `|| true` on the inverse-match stage (or use `! grep -q PATTERN`, or count with `grep -c` and compare to 0) — and prove the check can actually PASS by running it once against a known-compliant state before freezing it, not just against a known-failing one.
