statement: A frozen spec's own touch-scope regex (one Must-have criterion) can silently contradict another criterion's stated default file-location assumption within the SAME spec — the two criteria are drafted somewhat independently and neither the spec-writer nor an automated check cross-validates that a path a criterion names or implies is actually reachable under the touch-scope allow-list.

evidence: s9-analytics' spec.json v2 AC-26 named an additive Logic App recurrence trigger under infra/modules/scheduling as the DEFAULT nightly-scheduling mechanism (per the user's own spec-approval-gate amendment), but AC-01's touch-scope regex never included infra/modules/scheduling anywhere in its allow-list — only infra/modules/analytics and a handful of other paths. This wasn't caught at spec-freeze time; the planner discovered it live while trying to implement AC-26's stated default, and the plan-reviewer had to independently re-derive and formally rule on the contradiction (finding F4) before the plan could proceed with the only spec-compliant alternative (a Schedule-triggered Container Apps Job).

catch_next_time: Before freezing, spec-writer cross-checks every criterion that names or implies a specific file/directory location (e.g. AC-26 naming "infra/modules/scheduling" as a default mechanism) against the touch-scope regex (the AC-01-equivalent criterion) to confirm that path is actually reachable. A quick script matching every path literal mentioned across all criteria's statement/verify text against the touch-scope regex would catch this class mechanically before the spec is shown to the user for approval.
