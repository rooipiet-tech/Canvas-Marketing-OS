statement: This repo is built by a swarm of parallel sessions in sibling git worktrees (cmos-s0..s7), most unmerged to main at any given time; a sibling session may have already built the exact service/dependency this session's goal assumes doesn't exist yet, with directly reusable IaC/Docker/CI precedent.

evidence: On the s3-orchestrator run, the researcher did a full read of sibling worktree cmos-s2 (branch session/s2-vault, unmerged) and found it had already built the Vault service the goal assumed as a dependency — including a working container-app.bicep, sidecar-migration-job.bicep, smoke-test-job.bicep, and container-registry.bicep. [[L-0043]]'s domain.md constraint cited `git show --stat` on cmos-s2's commit to resolve a scope ambiguity, and the eventual plan mirrored cmos-s2's Bicep patterns almost verbatim.

catch_next_time: Before assuming a referenced service or dependency doesn't exist or must be built from scratch, run `git worktree list` / `git branch -a`, then `git log main..<sibling-branch> --stat` or `git show --stat <sibling-commit>` on any sibling worktree whose session goal sounds related, even if unmerged — read its actual files for directly reusable precedent (Bicep module shapes, Dockerfile patterns, CI job structure, API contracts) before designing from scratch.

companion (added 2026-07-31, s11-content): this learning covers probing for sibling work BEFORE design. The companion case is AFTER: when a sibling PR that spec research already depends on (fetched as a local git ref, scaffolding built around its unmerged state) merges mid-session, the correct response is not just to simplify away the now-unnecessary materialization scaffolding but to re-run a fresh empirical spot-check of the now-real merged files before relying on them — the merge event is exactly the moment stale assumptions (path locations, script behavior, tool availability) are most likely to have silently drifted from what research originally observed. On s11-content, PR6/PR7 merged mid-session; AC-05/06/21/28/29 were simplified from git-archive materialization to direct invocation only after spot-checking live that the merged content was byte-for-byte consistent with earlier research and re-running baseline tool invocations against the actual working tree.
