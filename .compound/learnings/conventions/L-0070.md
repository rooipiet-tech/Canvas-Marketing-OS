statement: When a session's subagents structurally lack live-infra access the orchestrator has, an acceptance criterion whose verify text conflates a locally-verifiable assertion with a live-infrastructure-verifiable assertion produces a headline pass-rate that undersells real build quality.

evidence: In this run, 12 of 32 criteria were scored failing because their verify text required querying a live cmos-dev DB/App Insights/Postgres unavailable to any subagent — but every locally-executable sub-assertion inside those same criteria passed and zero code defects were found. The resulting weighted_pass_rate_local_only (0.456) read as a failing build despite 100% local signal being clean; only reading each result's `reason` field revealed this.

catch_next_time: When an AC's verify text requires both a live-infra step and a locally-executable step, split it into two explicitly labeled sub-criteria up front (one scored against local/unit/mock evidence, one deferred to a live CI smoke job if the repo has one) instead of one AC whose single pass/fail conflates both. Lets a sandboxed tester report "N/N locally-verifiable criteria pass, M pending live-CI proof" instead of a single number that reads as failing when the local signal is 100% clean.
