statement: A human-authored GOAL's literal external-system identifier can itself be factually wrong — cross-diff it against an independently-authored, already-merged sibling-session artifact referencing the same external entity before freezing it into spec, when one exists.

evidence: The GOAL text for this session stated a Buffer LinkedIn channel id that was actually the X-profile channel id (a transcription error in the human's own prose). It was caught only because the plan-reviewer cross-checked it against S11's already-merged, independently-authored weekly-content-loop.yaml, which referenced the correct LinkedIn id — the sandbox had no live Buffer access to verify it any other way. The human confirmed the correction at the plan-review escalation gate.

catch_next_time: When a GOAL/spec embeds an external-system identifier (channel id, resource id, secret name, model id) and this repo already has an independently-authored, merged artifact referencing the same external entity (a sibling session's already-merged loop/config file, per [[L-0042]]'s parallel-worktree-swarm architecture), diff the two before freezing the identifier into spec — an independently-sourced merged artifact is stronger ground truth than fresh prose, even human-authored prose, and any disagreement is worth resolving before build starts. Extends [[L-0026]]'s "a document is a hypothesis about an external identifier, not proof" principle to human-authored GOAL text specifically, with a concrete verification method for repos with no live-API access.
