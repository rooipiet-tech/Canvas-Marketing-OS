statement: `git branch -r` only enumerates remote branches; a local-only,
never-pushed WIP branch is invisible to it and can hide an already-built (or
partially-built, possibly non-conformant) implementation of the exact capability
the current GOAL assumes doesn't exist. Prerequisite/dependency discovery must use
`git branch -a`, not `-r`.

evidence: research.md's `git branch -r` search concluded "No mcp-web
branch/service/config exists anywhere in the repo." The domain-expert later found
session/s5-mcp — a local-only branch, 206 files stale vs main, no PR — only
because it happened to run `git branch -a`. That branch's own tools.yaml used an
`inputSchema` property violating the very contracts/function-definition/tools.schema.json
shape the new build had to conform to, meaning two independently-authored unmerged
branches were mutually inconsistent.

catch_next_time: Researcher — always run `git branch -a` (local+remote) during
prerequisite-discovery, not `git branch -r`; when a relevant local-only branch is
found, also diff its artifact shape against the shared contract/schema this build
must conform to before treating it as a reference implementation — don't assume an
unmerged sibling branch is internally consistent with current contracts.
