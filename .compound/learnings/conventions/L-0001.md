statement: Before a spec/plan freezes any Must-have criterion that depends on live verification via an external CLI or local service (gh, docker, a database server, etc.), the spec-writer or plan-reviewer must first probe actual availability in the current sandbox rather than assuming it — AND when research documents a tool as unavailable, the spec-writer must mechanically translate that finding into the dependent AC's verify-command evidence bar at spec v1, not merely cite the finding in prose while leaving an unrunnable literal command in place for a later mid-loop amendment to catch.

evidence: On the canvas-marketing-os-foundation run, 21/40 acceptance criteria failed with failure_class=test (not build defects) because no `gh` CLI was installed/authenticated anywhere in the sandbox, no real Azure deployment existed yet, and no Docker/Postgres was available locally. None of this was fixable by further build iteration. Recurred on the s3-orchestrator run (2026-07-28): research.md already stated "no Docker, no local Python 3.12" in this sandbox (citing this exact learning), yet spec.json v1 still wrote 8 Must-have criteria with literal local pytest/psql-against-live-Postgres verify commands — requiring a mid-loop amendment (spec v4) to redefine the evidence bar (PASS if execution fails cleanly on the missing dependency, the test's source is confirmed defect-free, and CI's real job is confirmed to run it) that could have been written correctly into spec v1 directly from research's own findings.

catch_next_time: Run `gh --version && gh auth status`, `docker --version`, `python3.12 --version` (or the relevant interpreter), and check for admin/install rights BEFORE freezing a criterion that depends on them as a blocker. If unavailable, the spec-writer must write that specific AC's verify-command evidence bar to match reality at v1 (e.g. "PASS if verify fails cleanly due to missing X AND the CI job that provides X is confirmed to invoke this exact check") rather than writing a literal live-execution command and deferring the fix to a mid-loop amendment — probing availability is necessary but not sufficient; the finding must be mechanically translated into the frozen spec's verify commands themselves.
