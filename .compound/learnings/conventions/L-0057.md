statement: On this Windows/Git-Bash dev machine, spec-writer-authored verify commands that assume Unix tool/path semantics can pass syntax review yet be silently broken at execution time in three distinct ways: (a) `command -v python3 || command -v python` only checks PATH resolvability, not executability; (b) a literal `/tmp/...` path created by bash and consumed by a separately-invoked native-Windows-Python subprocess resolves to two different physical directories; (c) `git merge-base main HEAD` silently computes a wrong-but-plausible result when the local `main` ref is stale in a multi-worktree repo.

evidence: On the s11-content run, `command -v python3` resolved to a non-functional Windows Store app-execution-alias stub (exits 49 with an install nag) so the `||` fallback to real `python` never fired — affected 17 of 30 verify commands in the frozen spec.json before being caught mid-run. Separately, AC-28's scratch directory (`mkdir -p /tmp/ac28out` in bash) was invisible to the native Windows Python process that later tried to write/read it there (`tempfile.gettempdir()` resolves to an AppData path, not Git Bash's MSYS /tmp), causing a silent FileNotFoundError. Separately, `git merge-base main HEAD` produced 187 spuriously-offending files in AC-01's scope-guard check because local `main` was stale (checked out unreachable in a separate worktree, pinned pre-PR6/PR7) while `origin/main` had moved on 187 files' worth; merge-base against `origin/main` produced 0.

catch_next_time: Before freezing any spec verify command that resolves an interpreter, a scratch path, or a git ref, actually EXECUTE it once on the target dev environment and check the real exit code/output — not just read it. (1) Never trust `command -v <tool>` alone as a liveness check — invoke the resolved candidate with a trivial no-op (`"$TOOL" -c pass` or equivalent) and fall back only if that fails. (2) Never let a filesystem path cross a bash-shell/native-language-runtime boundary as a hardcoded string — have the consuming runtime generate its own scratch path (e.g. `tempfile.mkdtemp()`) and thread that resolved value through every subsequent step via a captured shell variable. (3) Any scope/diff-guard verify command must key off `origin/<default-branch>` (or another ref proven fresh), never a bare local branch name, in a multi-session/multi-worktree repo where local branch staleness is invisible until diffed.
