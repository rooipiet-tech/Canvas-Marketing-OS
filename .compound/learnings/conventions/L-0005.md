statement: Static, grep/regex-based spec verify commands (the kind frozen at spec-writing time) systematically cannot catch runtime/semantic bugs like lint failures from unimported forward-reference type annotations or URI-unsafe secret encoding — these are only caught by a separate post-build review pass that actually executes/parses the artifacts rather than grepping for keywords.

evidence: On the canvas-marketing-os-foundation run, 2 real bugs (a ruff F821 lint failure from a string type annotation `"NoReturn"` with no import; the base64-into-URI password bug, see L-0004) survived every criterion's literal grep-based verify command and were only caught by a 5-lens post-build review (output-reviewer, risk-security, data-residency, migration, agent-native), then fixed via a builder PATCH and re-verified with 0 regressions.

catch_next_time: Keep a mandatory post-build multi-lens review step (security, data-residency, migration-mechanism, agent-native-operability, general-output) as a standing stage distinct from the spec's own grep-based verify commands, precisely because grep/regex verification cannot exercise real interpreters/linters/parsers. Never treat "all spec verify commands pass" as sufficient evidence of correctness on its own.
