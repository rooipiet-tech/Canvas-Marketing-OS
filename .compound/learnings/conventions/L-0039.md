statement: Dynamic module loading from a directory whose name is not a valid Python identifier (numeric-prefixed and/or hyphenated, e.g. `functions/02-brand-steward-qa/`) cannot use a dotted `import`/`from...import` statement — it must use `importlib.util.spec_from_file_location` + `module_from_spec` + `exec_module` keyed by the resolved file path instead.
evidence: In the s6-registry build, plan v1's eval_harness.py design tried to dynamically import per-function tool_check modules by dotted path from directories following this repo's `NN-name` registry convention; the plan-reviewer caught this as blocker F1 (SyntaxError/ImportError risk), and plan v2 step 11 fixed it with importlib.util.spec_from_file_location keyed by directory path.
catch_next_time: When a plan proposes `import <x>` or `from <pkg> import <x>` targeting a path built from a digit-prefixed and/or hyphenated directory name, flag it as a blocker in plan-review and require importlib.util.spec_from_file_location-based dynamic loading instead of a dotted import.
