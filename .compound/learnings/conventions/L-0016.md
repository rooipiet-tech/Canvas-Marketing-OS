statement: This repo's Windows dev checkout has environment quirks worth actively
checking (not assuming) up front, corrected after an initial over-broad draft
wrongly asserted a fixed fact instead of a point-in-time check: (1) core.autocrlf
=true converts frozen contract files' committed LF endings to CRLF on checkout, so
hash-based frozen-contract verify scripts that hash raw working-tree bytes false-fail
locally even when content is correct. (2) `pytest` (when installed via `pip install
--user`) is not on PATH by default in Bash tool sessions on this machine — prefix
PATH with the pip user Scripts dir before invoking bare `pytest`; bare `python`
itself is already on PATH via the system Python install and needs no such prefix.
(3) Before pinning `requires-python` strictly in a new service's pyproject.toml,
check which interpreter versions are actually installed locally rather than
assuming a specific version is missing or present — installed-interpreter
availability on this machine changes over time (a 3.12 interpreter was added via uv
mid-session, after an earlier build step had already relaxed a version pin on the
assumption 3.12 was unavailable), so treat any "interpreter X not installed"
finding as a fact to re-check each session, not a durable repo property.

evidence: Verified directly: `git config core.autocrlf` = true on this checkout;
build_ref.json/test-report.json's AC-04 entries independently confirm the blob-hash
diagnosis technique resolves the false failure. `git log -p` shows requires-python
was relaxed on the assumption no 3.12 interpreter was available, but a 3.12
interpreter was installed via uv later the same session — the original unqualified
claim would have misled a future session into skipping a check that was already
resolved.

catch_next_time: Before writing or running any verify command that hashes/diffs
file bytes in this repo, compare against `git show HEAD:<path>` (blob content,
immune to autocrlf), not raw working-tree bytes. Before pinning requires-python
strictly in a new service's pyproject.toml, check the locally available
interpreter versions first (e.g. `py -0p`, `uv python list`) rather than assuming.
Prefix PATH with the pip user Scripts dir (not the whole Python install dir) when
invoking bare `pytest` via Bash in this repo.

reinforced 2026-07-30: `scripts/validate_contracts.py`'s breaking-change guard
hit this exact pattern (`full_path.read_bytes()` on all 7 frozen contract
files) and false-failed on 6 of them locally, while `ci.yml`'s
validate-contracts job (ubuntu-latest) stayed green across every recent
merge — confirming no real drift. Fixed by normalizing CRLF -> LF before
hashing rather than shelling out to `git show HEAD:`, so the check needs no
git availability assumption and still produces the same digest as blob
content for any already-LF file. This script predates L-0016 and wasn't
audited against it when written — worth a repo-wide grep for
`read_bytes()`/`open(..., "rb")` hashing in `scripts/` next time this class
of bug is suspected, rather than assuming it's a one-off.
