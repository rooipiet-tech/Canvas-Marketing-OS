statement: A plan step's or reviewer finding's own justification that new work "reuses"/"is a natural extension of" existing code can be plausible-sounding but factually false — never accept a reuse claim on the strength of its own plausibility.

evidence: plan-review (fix PV3-01) found a plan step's claim that Publisher's new vault_lookup.py was "a natural extension of a lookup the hash cross-check already performs" was false once checked directly against publish.py/models.py's own docstring: the existing check explicitly trusts NO caller-supplied hash and NO read of the assets.content_hash column today — no such existing lookup exists at all. The step was rewritten to describe the work honestly as new integration work.

catch_next_time: Whenever a plan step, PR description, or review finding contains a reuse/consistency claim ("this already does X", "mirrors the existing Y pattern", "this reuses Z"), the reviewing role must independently grep/read the specifically-named file(s) and confirm the claim before accepting it as justification for scope or risk classification. Generalizes [[L-0038]] from "inferred architecture" to any actor's explicit "this reuses existing code" claim, at plan-review time rather than spec-freeze time.
