statement: Any client name, statistic, or claim sourced from confidential sales decks (Delta finalist deck, Sage decks, Powerfleet/Gert-Hestony deck, Delta references) requires a written permission-register clearance before it can be used in public-facing marketing content. An unresolved clearance state — including "reference available on request" — is a blocking condition, not a soft caveat; "on request" means NOT cleared, not a pending-but-acceptable state.

evidence: docs/positioning.md §7 ("Gaps and watch-outs") explicitly flags Imperial and Rotork references as unconfirmed for public use ("reference available on request… confirm before public use"), and separately notes the Imperial reference contact's email domain doesn't match the Imperial organisation — a further reason not to treat "on request" as good enough. functions/brand-steward-qa/ enforces this as a hard blocking rule (prompt.md, category "permission_rule"), with an eval case (evals/uncleared-client-name-blocks.json) asserting a draft naming "Imperial Logistics" with sales-deck-sourced stats must return verdict "fail", regardless of how strong the copy's positioning fidelity otherwise is.

catch_next_time: Any Canvas Marketing OS function that drafts or reviews public-facing copy referencing a named client, or a sales-deck-sourced number/claim, must check for a corresponding permission-register entry and treat its absence — including an "available on request" state — as a blocking failure, not a warning. Until a real permission-register store exists, any such check must fail closed (assume "no entry found" rather than assuming clearance) — see functions/brand-steward-qa/tools.yaml's check_permission_register tool description. Building the actual permission-register store (and backfilling entries for currently-cleared references, if any) is an open follow-up, not yet done as of this learning.
