statement: Azure Key Vault (standard tier, software-protected keys) cannot create, sign, or verify EdDSA (Ed25519) keys — supported key types/algorithms are RSA (2048/3072/4096, RS256/PS256) and EC P-256/P-384/P-521/P-256K (ES256/ES384/ES512) only.

evidence: Confirmed against `kv-cmos-dev-dziw5kptw2qe` (standard SKU, per `infra/modules/key-vault.bicep`) via Microsoft Learn's "Key types, algorithms, and operations" documentation and Azure/azure-cli issue #26898 ("Unsupported curve: Ed25519"). This directly drove the S4 governance build's gate-token signing algorithm choice: RS256 was selected as the default (over the contract-allowed EdDSA option) specifically because this vault tier cannot produce it — a real, checkable architectural decision, not an unused fact.

catch_next_time: Before speccing or accepting EdDSA/Ed25519 signing against an Azure-Key-Vault-backed key, confirm the vault's tier and its supported key/algorithm matrix first. Default Key-Vault-backed signing designs to RS256/PS256/ES256 unless a Managed HSM with confirmed Ed25519 support is explicitly in use.
