statement: A GitHub Actions job authenticating `anthropics/claude-code-action` via a
metered `ANTHROPIC_API_KEY` fails silently and misleadingly once the account's
monthly API budget cap is reached: the SDK still initializes ("Claude Code
initialized"), burns real wall-clock time (observed 367ms to ~174s across
different runs), and then returns
`{"type":"result","subtype":"success","is_error":true,"total_cost_usd":0,"modelUsage":{}}`
-- a `subtype: "success"` alongside `is_error: true`, zero recorded cost, and
empty usage. The action's default output redaction ("full output hidden for
security") hides whatever real error text the SDK produced, so the job logs
alone give no hint that it is a budget/billing issue rather than a bug in the
prompt, the skill, or the workflow YAML. This broke every claude-code-action
workflow in this repo (`claude-review` AND `claude-system-audit`)
simultaneously and silently for six days (2026-09-04 13:55 UTC through
2026-09-10) before being traced to the monthly budget cap.

evidence: Reviewed workflow run history for `claude-review.yml` and
`claude-system-audit.yml`. Run 64 (claude-review, 2026-09-04 13:36 UTC)
succeeded normally; run 65 (2026-09-04 13:55 UTC) and every run after it --
across both workflows, across different models (`claude-sonnet-5` and
`claude-opus-5[1m]`), across different audit lenses and different PRs --
failed with the identical `is_error:true`/`$0`-cost/empty-`modelUsage`
signature. A `workflow_dispatch` diagnostic with `show_full_output: true`
failed to capture the real error because the action independently refuses to
exchange its OIDC token for an app token when the dispatching ref's workflow
file differs from the default branch's copy ("Workflow validation failed...
must exist and have identical content to the version on the repository's
default branch") -- a separate anti-tampering guard, not the underlying bug,
and it silently reports the step as `success` while skipping Claude entirely.
Root cause (monthly `ANTHROPIC_API_KEY` budget cap reached) was confirmed by
the account owner directly, not from the CI logs.

catch_next_time: When every claude-code-action step across multiple unrelated
workflows starts failing at the same moment with `is_error:true`,
`total_cost_usd:0`, and empty `modelUsage` -- regardless of duration, model, or
prompt -- suspect account-level billing/budget/auth before touching the
workflow YAML, the skill, or the prompt. To get the actual error text out of a
redacted run, `show_full_output: true` (or GitHub's debug re-run) only works
when the workflow file being executed is byte-identical to the default
branch's copy -- a diagnostic edit made on a feature/PR branch silently no-ops
instead of running Claude, and itself reports `conclusion: success`. To
sidestep both the redaction and the budget cap at once, authenticate via
`claude_code_oauth_token` (minted from a Claude subscription with
`claude setup-token`) instead of a metered `anthropic_api_key` -- this repo's
`docs/continuous-review.md` already documented that swap as an option before
this incident forced it.
