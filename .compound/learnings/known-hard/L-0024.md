statement: `az containerapp job logs show` requires an explicit `--container
<name>` argument even for a single-container job — it does not default to
the job's only container. Omitting it fails fast with a clear CLI usage
error (`the following arguments are required: --container`), unlike L-0023's
silent-failure class.

evidence: `deploy-gateway.yml` called `az containerapp job logs show -g ...
-n caj-vault-query --execution "$EXEC_NAME"` (no `--container`) and failed
41 seconds in with the CLI's own usage message. `vault-query-job.bicep`
declares exactly one container (`vault-query`); `caj-gateway-smoke` also has
exactly one (now explicitly named `gateway-smoke` via `--container-name` at
creation, rather than left to whatever the CLI defaults to).

catch_next_time: Any `az containerapp job logs show` invocation needs
`--container <container-name>` matching the job's Bicep-declared container
`name` (or an explicitly-set `--container-name` at job create/update time,
if the job wasn't declared in Bicep) — check the template's container name
up front rather than assuming single-container jobs don't need the flag.
